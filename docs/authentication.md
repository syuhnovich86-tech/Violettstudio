# Пользователи и вход

Контрольная точка этапа 3 завершена 2026-08-14.

## Реализовано

- иерархия ролей `owner`, `admin` и `employee`;
- безопасное хэширование паролей Argon2id;
- серверные сессии с хранением только SHA-256 хэша токена;
- `HttpOnly` cookie и CSRF-защита изменяющих запросов;
- ограничение повторных неверных попыток входа;
- создание, просмотр, отключение пользователей и сброс пароля;
- отзыв сессий при отключении пользователя или сбросе пароля;
- самостоятельная смена пароля после входа с проверкой текущего пароля и отзывом остальных сеансов;
- защищённая запись владельца, которую нельзя создать или отключить через веб-интерфейс;
- администраторы студии управляют сотрудниками, но не владельцем и не другими администраторами;
- мобильный экран входа и базовая панель пользователей.

Реальные пользователи и пароли не зашиваются в код или миграции. Владелец системы создаётся интерактивной командой после развёртывания, затем создаёт Марию и Виолетту как администраторов студии. Они добавляют сотрудников через интерфейс.

Предварительный список из девяти пользователей хранится в `docs/employees-draft.md` и будет использован при настройке Raspberry Pi.

## Создание владельца после развёртывания

```sh
docker compose exec app python -m vita29.cli create-owner --name "Владелец" --login owner
```

Пароль вводится дважды без отображения на экране и не сохраняется в истории команд.

При локальной проверке по HTTP `VITA29_COOKIE_SECURE=false`. Перед публикацией через домен и HTTPS настройка обязательно меняется на `true`.

## Аварийный сброс пароля

Сброс выполняется на сервере с интерактивным вводом нового пароля и завершает все прежние сессии пользователя:

```sh
docker compose exec app python -m vita29.cli reset-password --login stepan
```
