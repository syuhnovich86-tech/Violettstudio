## Сборка и установка

Для существующего сервера используется `deploy/compose.yaml`. Перед изменениями нужна согласованная резервная копия SQLite, медиа и конфигурации. Секреты и рабочая БД в Git не хранятся.

```sh
docker compose -f deploy/compose.yaml config --quiet
docker compose -f deploy/compose.yaml build app
docker compose -f deploy/compose.yaml up -d --no-deps app
docker compose -f deploy/compose.yaml exec -T caddy caddy validate --config /etc/caddy/Caddyfile
docker compose -f deploy/compose.yaml exec -T caddy caddy reload --config /etc/caddy/Caddyfile
```

Миграция запускается командой контейнера до Uvicorn. Для импорта запускайте отдельный сервис `importer` только если он нужен в этой установке; не создавайте второго обработчика рядом с уже работающей службой импорта.

Требуемые внешние данные и службы:

- `deploy/.env` с настройками конкретного сервера и `/opt/vita29/secrets` с закрытыми файлами интеграций;
- рабочие каталоги `/srv/vita29/app-data`, `/srv/vita29/media`, при необходимости geonames/import;
- ранее опубликованные Android APK и Expo Updates;
- действующие аккаунты и хранилище сессий мессенджеров;
- отдельные службы публичного сайта и `website-leads`, используемые Caddy; Unix-сокет публичного сайта монтируется из `/opt/vita29/public-website/run`;
- сертификаты Caddy, DNS и проброс портов, настроенные для конкретного адреса сервера.

Этот архив является снимком исходников и конфигурации приложения, а не полным бэкапом машины. Он не содержит сайт, пользовательские файлы, пароли, сессии мессенджеров или рабочую БД. На новой машине перечисленные зависимости нужно восстановить отдельно. Образы базовых слоёв и зависимости не полностью закреплены по digest; повторная сборка не обязана давать побайтово тот же Docker ID.

## Откат

На действующем сервере оставлены образы `deploy-app:before-security-20261115`, `deploy-app:security-20261115`, `deploy-app:content-removal-20261115`. Перед миграцией сделана SQLite-копия `backups/vita29.before-plan-removal-20261115.db` в каталоге данных, с правами 0600.

Для исправления проблем с интерфейсом можно вернуть предыдущий образ, сохранив текущую БД. Не заменяйте живую БД старой копией поверх новых загрузок и публикаций. Колонка удаления nullable и допускает чтение старым кодом, но старый код не учитывает удалённые из плана карточки — при полном откате планировщик необходимо остановить до отдельной сверки.

DNS-защита почты и настройки роутера существуют вне Docker/Compose. Их отдельная проверка и подробный отчёт безопасности сохранены локально; публикация этих материалов с внутренними сведениями в репозиторий не выполняется.
